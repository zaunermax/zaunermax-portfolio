# Quest Office — art & tech contract

The `/lab/1-quest` world is being redesigned from a WoW-style fantasy valley into a **cute, whimsical
voxel office** (Hytale / Minecraft Dungeons feel; nods to *The IT Crowd* and *The Office*). This file is
the shared contract between the Blender asset work (`tools/quest-voxel/`) and the game engine
(`src/app/(lab)/lab/1-quest/`). If you need to deviate, update this file in the same change.

## Look

- Chunky voxels with **pixel-art surfaces**: every voxel face carries its own colour, with a small
  deterministic per-voxel jitter (±3–6 % lightness, slight hue drift) so flat areas read as hand-pixelled
  texture rather than plastic. Accent details (seams, buttons, wood grain, fabric stitches) are drawn
  with 1-voxel colour changes, like pixel art.
- Cute proportions: slightly chunky, rounded silhouettes via stepped voxels, bevel-like 1-voxel insets,
  oversized readable details (big mug handle, big keycaps). Nothing realistic-thin: minimum feature is
  1 voxel.
- Palette: warm, saturated but soft. Wood: honey/oak. Fabrics: teal, coral, mustard, lilac, sage.
  Metal: cool greys with a blue tint. Screens: deep navy with bright pixel UI (glowing).
  Plants: two-to-three greens with yellow-green highlights and dark undersides. Avoid pure black and
  pure white; darkest ≈ #2b2433, lightest ≈ #f4efe6.
- Glossy screens, chrome, glass and awards share sparse 1-voxel cream glints. Landmark LEDs use
  small cyan/cream `voxel_glow` accents; the redeploy server has a cyan front strip and glowing top vent.
- Seen from a fixed ~45° (pitch ≈ 50°) three-quarter top-down camera that looks *north* (toward −Z).
  Fronts face **+Z (south, toward the camera)**. Tops and fronts carry the detail; backs can be plain.

## Units & conventions (glTF)

- 1 world unit = 1 floor tile = **16 voxels**. Voxel edge = `1/16 = 0.0625`.
- glTF Y-up. Front faces **+Z**. Footprint `w × d` tiles spans X × Z.
- Origin: **centre of the footprint, at the bottom (y = 0)**. Wall-mounted assets: origin at the
  bottom-centre of the back face, back face at z = 0, extending into +Z.
- Key heights (voxels): floor 0 · seat 7 · desk/table top **12** (0.75) · counter top **15** (≈0.94) ·
  door 34 · wall height in engine 3 tiles (48) but walls facing the camera are cut down to 6 voxels.
- Desk-top items have their origin at their own bottom so the engine can place them at y = 0.75.
- Tall furniture deliberately exceeds the ≈26-voxel cast: fridge 32, vending 33, server rack 34,
  bookshelves 32, ficus 35 and arcade 32. Whiteboard and floor lamp are 30; sofa backs are 15.
- Materials (exactly these names, all using the `COLOR_0` vertex colour attribute):
  palette colours and jitter are authored in sRGB, then converted to **linear RGB** for glTF
  `COLOR_0`, as required by glTF/three.js. Do not apply a second sRGB-to-linear conversion in the engine.
  - `voxel` — opaque, rough, non-metal. Default for everything.
  - `voxel_glow` — screens, LEDs, lamp shades, neon. Engine renders it emissive (colour × intensity).
  - `voxel_glass` — windows, fish tank, glass doors. Engine renders it translucent.
- Meshes: one mesh per asset (or per animated part), hidden internal faces removed, no UVs needed,
  flat normals. Budget: props ≤ 3 000 tris, large furniture ≤ 6 000, characters ≤ 2 500.

## Delivery

- Blender sources are **Python** under `tools/quest-voxel/` (voxel models defined in code, built and
  exported headlessly with `blender -b --python ...`). No hand-edited `.blend` files required.
- Per-asset GLBs + preview PNGs go to `tools/quest-voxel/out/` (gitignored previews are fine).
- The game loads **one kit file per family** from `public/lab/quest/`:
  - `office-kit.glb` — every non-character asset; each asset is a **top-level node named by its id**.
  - `characters.glb` — each character is a top-level node named by its id with child part nodes
    `head`, `body`, `arm_l`, `arm_r`, `leg_l`, `leg_r` (animals: `head`, `body`, `tail`, `leg_fl`,
    `leg_fr`, `leg_bl`, `leg_br`; robots: `body`, `top`). Each part's pivot sits at its joint
    (shoulder, hip, neck) so the engine can rotate parts for walk/idle/sit/wave.
- `public/lab/quest/kit-manifest.json`: `{ "<id>": { "footprint": [w, d], "height": <units>,
  "wall": bool, "family": "<family>", "tags": [...] } }` generated by the build script.
- The engine must tolerate missing ids (render a footprint-sized pastel placeholder box).

### Toolkit implementation clarifications

- Python voxel coordinates use the same X/Y/Z axes as the game, integer cell minima, and half-open
  boxes. Only the preview adapter converts to Blender's Z-up axes. The deterministic GLB writer
  writes Y-up directly. Footprint sizes describe placement bounds, not a requirement to fill every cell.
- An unsupported connecting span such as `desk_mid` retains its origin on the floor at y = 0;
  its lowest occupied voxel can be above that origin. Desktop props still sit at their own bottom.
- Character part geometry is authored in absolute bind-pose voxel coordinates. Pivots are joint
  positions in those coordinates; the exporter subtracts the pivot from vertices and puts it into
  the child node translation. `l/r` mean the character's own left/right: left is +X when facing +Z.
- Each part node also has `extras.part` with its canonical name. GLB node names are exactly those
  above, but three.js GLTFLoader makes duplicate names unique across the loaded scene (e.g. `head_1`).
  Find a character's immediate child by `child.userData.part`, rather than its rewritten `.name`.
  A part using multiple materials may load as a Group containing primitive meshes; rotate the part
  node, not its primitive children.
- `voxel_glow` has `extras.vertexEmission: true` and `extras.intensity: 0.65`. The engine supplies
  emission from vertex colour as already specified above; stock glTF viewers show its base colour.
  glTF has no built-in per-vertex emissive input. Glass uses alpha blending at 0.36.
- The mesher removes shared opaque/opaque and glass/glass faces. At an opaque/glass boundary it
  retains only the opaque surface, preventing coincident faces without exposing holes through glass.
- Builds always discover all `assets/*.py` definitions and rebuild both complete kits and the manifest,
  including when `--only` limits individual exports/previews. Generated previews and runtime caches
  are excluded from the kits. No triangle-budget increases were needed for the reference assets.

## Engine contract (summary)

- The office is a tile grid (≈ 40 × 28). Walls, floors, doors, glass partitions, rugs-as-floor and
  room lighting are **procedural in the engine** (with the same voxel/pixel look: per-tile pixel
  textures generated on a canvas, voxel-thick walls, camera-facing walls cut low).
- Furniture placement is deterministic code (seeded RNG + value/simplex noise + autotile rules); the
  LLM only writes the creative brief (company, zones, event, characters, lines, names).

## Modular character extension

See [CHARACTERS.md](CHARACTERS.md) for the complete assembly contract. A third kit,
`character-parts.glb`, contains 45 top-level `<category>/<id>` nodes, accompanied by
`character-parts.json` with palettes, compatibility, rig pivots and staff recipes.
These components are separate from the fixed characters and the placement manifest.
`extras.id` preserves their unsanitized names in GLTFLoader. Their bone children
retain `extras.part` and the existing pivots.

Modular variable colours use FLOAT `_SLOT` (three.js `_slot`) and linear `COLOR_0`
multipliers (FLOAT in raw exports, normalized UNSIGNED_BYTE in public kits);
slot 0, or a missing attribute, means baked linear colour. Read normalized colour
channels through attribute getters and promote to float storage before recolouring.
Runtime RGB is `linear(palette[slot]) * sourceCOLOR_0.rgb` for nonzero slots. Skin,
skin_shade, hair, hair_shade, top, top_trim, bottom, shoes and accent are the nine
variable slots. Preserve source multipliers and clone geometry before recolouring.
The library must be coloured before display. Materials keep the same three names.

All three public kits require `EXT_meshopt_compression` and `KHR_mesh_quantization`.
Drei 10.7.9 enables its bundled meshopt decoder by default; standalone GLTFLoader
needs `setMeshoptDecoder`. See CHARACTERS.md for loader and attribute details.
Positions, normals, pivots, names, extras and triangle order remain exact; linear
colours are packed with at most 1/510 error. The raw writer and source mesher remain
unchanged. Every kit is decoded and compared before atomic publication.

Fixed characters retain the 2,500-triangle budget. A modular assembled person has
a 4,500-triangle cap because independent components preserve boundary faces and
support more accessories; exhaustive four-accessory fit cases reach 4,160. Tiny
front-only pixel decal offsets are the sole exception to integer voxel surfaces.

`characters.glb` also includes `robo_courier`, `drone_cam`, `robo_barista`,
`plant_bot`, `office_parrot` and `office_hamster`. Besides existing rigs, animated
sets now include body + four rotor_* parts; body/head/wing_l/wing_r/tail; and
body/head/ball. Resolve actual `userData.part` values instead of assuming a humanoid
rig. Max remains bespoke and unchanged.
